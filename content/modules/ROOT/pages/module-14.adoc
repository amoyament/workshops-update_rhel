= System Roles (Controller-driven)
:toc:
:toc-placement: auto

In this exercise, you will use pre-existing content (roles and collections) from Automation Hub and Ansible Galaxy to configure hosts via Ansible Automation Controller. You will leverage Linux System Roles and RHEL System Roles with a simple Survey-driven job to manage firewall and timesync configuration.

=== Step 1 - Create the project

In the Ansible Automation Controller UI navigate to *Automation Execution → Projects* and click *Create project*.

Project fields:

[cols="1,1"]
|===
|Parameter |Value

|Name
|System Roles Project

|Organization
|Default

|Execution Environment
|Default execution environment

|Source Control Type
|Git

|Source Control URL
|`https://github.com/ansible/product-demos`
|===

Click *Create project* and wait for the sync to complete.

image::exercise-2-7-system-roles/demo-project.png[system roles project,link=self,window=_blank]

=== Step 2 - Review the playbook

Open the repository in your browser and navigate to:

* linux/hardening.yml
** link:https://github.com/ansible/product-demos/blob/main/linux/hardening.yml[]

Relevant tasks (roles are conditionally included):

[source,yaml,role=copypaste]
----
- name: Configure Firewall
  when: harden_firewall | bool
  ansible.builtin.include_role:
    name: linux-system-roles.firewall

- name: Configure Timesync
  when: harden_time | bool
  ansible.builtin.include_role:
    name: redhat.rhel_system_roles.timesync
----

Role naming tips:

* Collection role: namespace.collection.role (e.g., redhat.rhel_system_roles.timesync)
* Standalone role: namespace.role (e.g., linux-system-roles.firewall)

=== Step 3 - About Linux and RHEL System Roles

System Roles provide consistent interfaces for subsystem configuration, abstracting implementation differences.

Examples:

* firewall (linux-system-roles.firewall)
** Controls services such as http/https and more
** Example var:
+
[source,yaml,role=copypaste]
----
vars:
  firewall:
    service: 'http'
    state: 'enabled'
----

* timesync (redhat.rhel_system_roles.timesync)
** Manages chrony or ntp as appropriate
** Example var:
+
[source,yaml,role=copypaste]
----
vars:
  timesync_ntp_servers:
    - hostname: pool.ntp.org
      iburst: yes
----

=== Step 4 - Create and launch the Job Template with a Survey

. In Controller, go to *Automation Execution → Templates*, click the *Create template* dropdown and select *Create job template*.

Template fields:

[cols="1,1"]
|===
|Parameter |Value

|Name
|SERVER / Hardening

|Job Type
|Run

|Inventory
|Workshop Inventory

|Project
|System Roles Project

|Playbook
|`linux/hardening.yml`

|Execution Environment
|Default execution environment

|Credentials
|Workshop Credential
|===

image::exercise-2-7-system-roles/job.png[job template,link=self,window=_blank]

. Add a Survey to toggle roles:

* Survey Questions:
** CONFIGURE FIREWALL? (boolean) → sets harden_firewall
** CONFIGURE TIME? (boolean) → sets harden_time

image::exercise-2-7-system-roles/survey.png[survey,link=self,window=_blank]

Click Launch:

image::exercise-2-7-system-roles/launch.png[launch,link=self,window=_blank]

If a confirmation step is shown:

image::exercise-2-7-system-roles/next.png[next button,link=self,window=_blank]

Review the EXTRA VARIABLES to see how the survey sets the role switches and proceed.

=== Step 5 - Verify configuration

From the control node, verify time configuration:

[source,bash,role=copypaste]
----
ansible node01 -i hosts -m command -a "systemctl status chronyd.service"
----

[source,bash,role=copypaste]
----
ansible node01 -i hosts -m command -a "timedatectl"
----

Example commands:

[source,bash,role=copypaste]
----
chronyc tracking
chronyc sources
chronyc sourcestats
chronyc activity
----
